1. Multi-Tenant SaaS Invoicing & Billing Platform
Problem: Small businesses need to create customers, generate recurring invoices, accept payments, and see a real-time balance — with strict tenant data isolation. Blueprint patterns exercised: Shared-tables multi-tenancy (§8.8) with tenant_id scoping on every query, idempotency keys for payment webhooks (§7.5, §7.3), outbox pattern for "invoice paid → send receipt" (§8.5.1), NestJS modular structure (billing, customers, payments modules). Stack: Next.js (dashboard) + NestJS (payments module wraps a payment provider adapter) + PostgreSQL/Prisma + BullMQ (async receipt emails, PDF generation) + Redis (rate limit on payment endpoint). What makes it resume-worthy: You have to prove cross-tenant isolation with actual tests (§14.2), which is a specific, checkable claim most portfolios never demonstrate.
